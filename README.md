# TrccSharp — экран СЖО Thermalright без TRCC

Приложение для LCD-экрана на помпе `Thermalright Frozen Warframe 360 V2 ARGB`
(и других панелей семейства Warframe/Vision). Работает напрямую с USB-устройством,
без `TRCC.exe`, `USBLCDNEW.exe`, без служб и фоновых процессов-посредников.

Проверено на живой панели:

```
0416:5302  USBDISPLAY
  MI_00  HIDClass / HidUsb    ← рабочий канал
  MI_01  USBDevice / WINUSB   ← недоступен без INF от TRCC
```

## Что выяснено про железо (и почему это важно)

Handshake панели отвечает:

```
PM=58 SUB=0 FBL=58   (Frozen Warframe SE / 4.07)
серийник: 42503231393430...
```

Отсюда профиль: **320×240, RGB565, little-endian, поворот кадра 90°** —
на провод уходит растр 240×320.

Четыре вещи, без которых панель показывает мусор или вообще ничего
(все проверены перебором на устройстве):

1. **Транспорт — HID, отчётами по 513 байт.** Первый байт отчёта — Report ID (0),
   дальше 512 байт данных. WinUSB-интерфейс `MI_01` не публикует ни одного
   device interface GUID, пока не установлен INF из TRCC, поэтому открыть его
   через `CreateFile`/WinUSB API нельзя. HID же доступен сразу.
2. **Init-пакет `DA DB DC DD … cmd=1` отправлять нельзя.** Прошивка от него
   перезагружается, и все кадры, отправленные в следующие секунды, теряются.
   Handshake делается один раз в отдельном подключении, рабочий канал его не видит.
3. **Кадр уходит потоком 512-байтных записей**, а не одним блоком: прошивка
   читает отчёты фиксированного размера и «защёлкивает» картинку только так.
4. **Поворот 90°.** Кадр композится 320×240 и поворачивается в 240×320.
   Без поворота изображение разъезжается в полосы (неверная ширина строки).

Формат заголовка кадра (20 байт):

```
DA DB DC DD | 02 00 | 01 00 | 240 | 320 | 02 00 00 00 | len (LE32)
```

## Датчики GPU (AMD ADL)

```
ADL2_Main_Control_Create → ADL2_Adapter_NumberOfAdapters_Get(контекст!)
  → ADL2_Adapter_Active_Get → индекс активного адаптера
ADL2_New_QueryPMLogData_Get → ADLPMLogDataOutput
  { int size; { int supported; int value; } sensors[256]; }
```

Индексы датчиков из `adl_defines.h`: `PMLOG_TEMPERATURE_EDGE` = 8,
`MEM` = 9, `VRMVDD` = 11, `HOTSPOT` = 27. Значения — уже градусы Цельсия.

На RX 5700 XT (Navi 10) `ADL2_OverdriveN_Temperature_Get` и
`ADL2_Overdrive6_Temperature_Get` возвращают `ADL_ERR_NOT_SUPPORTED` (-8):
эта карта обслуживается Overdrive8, температура доступна только через PMLog.
Считать число адаптеров надо контекстной функцией `ADL2_...`: глобальная
`ADL_Adapter_NumberOfAdapters_Get` здесь отдаёт 0.

## Установка

Готовый установщик и портативный exe — в [Releases](https://github.com/osveyri-hash/trcc-sharp/releases/latest):

- `TrccSharp-0.3.0-setup.exe` — ставится в `%LOCALAPPDATA%\Programs\TrccSharp` без прав администратора. Создаёт ярлык в меню «Пуск», ярлык на рабочем столе (галочка в установщике) и, если отмечен автозапуск, запускается при входе в Windows скрыто в трее.
- `TrccSharp.exe` — портативный вариант: просто запустить, ничего не устанавливается. Сжат в один файл (~69 МБ).
- `TrccSharp-lite.exe` — лёгкий вариант (~1 МБ): требует установленный **.NET 8 Desktop Runtime**. Запускается быстрее и не распаковывает runtime во временную папку.
- `TrccSharp-lite-0.3.0-setup.exe` — установщик лёгкой сборки (~0,7 МБ): те же ярлыки и автозапуск, но ставится 1 МБ вместо 69 МБ. Нужен .NET 8 Desktop Runtime.

## Запуск

Готовый бинарник не требует установленного .NET:

```
trcc-sharp\dist\TrccSharp.exe
trcc-sharp\dist\TrccSharp.exe --auto              # сразу начинать вывод (для автозагрузки)
trcc-sharp\dist\TrccSharp.exe --auto --fps 5      # вывод на 5 кадрах/с
trcc-sharp\dist\TrccSharp.exe --auto --media "C:\gifs\cat.gif"   # сразу своя гифка
trcc-sharp\dist\TrccSharp.exe --auto --brightness 60             # яркость 60 %
```

Приложение само прописывается в автозагрузку Windows (ветка
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, флаг `--autostart`):
при входе в систему окно не показывается, а экран СЖО сразу получает картинку.
Отключить можно переключателем «АВТОЗАПУСК» в настройках.

Из исходников:

```powershell
dotnet run --project .\trcc-sharp\src\TrccSharp.App -- --auto
```

## Диагностика

Отдельная консольная утилита — ей же снимались все факты выше:

```powershell
$probe = ".\trcc-sharp\src\TrccSharp.Probe\bin\Release\net8.0-windows\trcc-probe.dll"

dotnet $probe list                                   # что найдено в USB/HID
dotnet $probe probe --transport hid                  # handshake + профиль панели
dotnet $probe pattern --no-init --edges --rotate 90  # цветные полосы по краям
dotnet $probe pattern --no-init --rotate 90          # тестовая картинка
dotnet $probe sweep --transport hid                  # перебор раскладок кадра
dotnet $probe gpu                                    # датчики GPU через AMD ADL
```

## Возможности приложения

- живое превью 320×240 в окне, ровно то, что уходит на панель;
- темы: «Монитор» (CPU, RAM, GPU-темп, uptime), «Часы», «Медиа»;
- у «Монитора» одиннадцать готовых видов, они переключаются строкой «ВИД»: обычный,
  минимал, график, кольца, полосы, шкала, типограф, сетка, список, волна, разрез;
- «График» — крупная загрузка ЦП и две кривые за последние ~50 секунд: ЦП акцентом,
  ОЗУ серым, со свежим отсчётом точкой на правом краю;
- «Кольца» — три круговых индикатора: ЦП, ОЗУ и температура ГП по шкале 30–90 °C;
- «Свой» вид — конструктор панели: объекты (ЦП, ОЗУ, ГП, система, время) добавляются
  кнопкой «Добавить», тащатся мышью прямо по превью и удаляются кнопкой «Удалить»;
  выбранный объект масштабируется ползунком «Масштаб» (50–300 %);
  раскладка запоминается в настройках;
- кнопка «Вернуть в исходное» сбрасывает всё оформление и раскладку к заводскому виду;
- оформление кадра: любой системный шрифт, цвет текста (тушь темы, серый или
  акцент) и яркость фона 20–100 %; по умолчанию фон затемнён на 50 %,
- содержимое любого вида двигается мышью прямо по превью, а ползунок «Масштаб»
  увеличивает его до 160 %; сдвиг и масштаб запоминаются отдельно для каждого вида,
  кнопка «Сброс» возвращает вид к исходному;
- тема «Медиа»: своя гифка, фото или видео на весь экран панели с зацикливанием
  (картинка растягивается по большей стороне, лишнее обрезается — без чёрных полей);
- у «Монитора» и «Часов» можно поставить свой фон — фото под данными, с кнопкой
  сброса к чистому листу;
- файл выбирается кнопкой или перетаскиванием в окно, выбор запоминается
  в `%APPDATA%\TrccSharp\settings.json` вместе с темой, частотой и яркостью;
- яркость экрана 10–100 %: как и в оригинальном TRCC, это программная подстройка
  каналов перед кодированием в RGB565 (команд в панель не уходит), превью
  затемняется тем же коэффициентом;
- частота кадров 1–10 в секунду для тем с датчиками; в теме «Медиа» ритм берётся
  у самого файла (GIF — задержки кадров, видео — его частота, вплоть до 30 кадр/с);
- датчики без сторонних пакетов: `GetSystemTimes` (CPU), `GlobalMemoryStatusEx`
  (RAM), AMD ADL `ADL2_New_QueryPMLogData_Get` (температура GPU, AMD);
  на NVIDIA — запасной путь через `nvidia-smi`;
- в теме «Медиа» датчики не опрашиваются вообще — кадр берётся из файла;
- статичное фото не перерисовывается: кадр уходит при изменении и редким
  keep-alive (раз в секунду), чтобы панель не вернулась к своей картинке;
- закрытие окна крестиком прячет его в трей, но вывод продолжается: картинка
  на панели остаётся. Полный выход — через меню иконки в трее;
- автозапуск с Windows: при входе в систему окно не появляется, а экран СЖО
  сразу получает сохранённую тему с картинкой;
- «АВТОВЫВОД» — переключатель под «АВТОЗАПУСКОМ»: сразу включать вывод при
  открытии приложения. Если выключить, после запуска нужно нажать «ЗАПУСТИТЬ ВЫВОД»;
- 10 готовых тем «Монитора» в «МОИ ТЕМЫ»: пять светлых и пять тёмных с разными
  акцентами — роза, лаванда, олива, янтарь, сталь;
- меню оформления (значок палитры в шапке) — восемь тем с иконками в две
  колонки: «Светлая», «Тёмная», «Океан», «Графит», «Сакура», «Матрица»,
  «Лес», «OLED»; выбранная строка подсвечена точкой, у каждой темы есть
  светлый и тёмный вариант (кружок «луна» рядом с палитрой);
- под выбором медиа/фона — строка «НЕДАВНИЕ»: четыре последних файла с
  миниатюрами и форматом (JPG, PNG, GIF, MP4…), нажатие применяет файл снова;
- переподключение и честные ошибки в логе;
- панель, отвалившаяся на ходу, поднимается сама: канал закрывается и открывается
  заново каждые 5 с, петля кадров переживает сбой одного кадра, а кадр после
  переподключения уходит целиком. Если 3 попытки подряд не удались, под статусом
  появляется кнопка «СБРОСИТЬ ПАНЕЛЬ (USB)»: она снимает USB-устройство панели и
  заставляет Windows перечислить его заново — это лечит зависшую прошивку панели
  без перезагрузки компьютера (нужен ответ на запрос прав администратора);
- журнал панели — `%APPDATA%\TrccSharp\panel.log`: подключения, сбои отправки,
  переподключения. По нему видно, когда и почему экран погас.

## Окно приложения

- две вкладки в шапке: «НАСТРОЙКИ» (тема, медиа, FPS, яркость)
  и «ТЕМЫ» (сохранённые наборы);
- тема окна выбирается в меню оформления (значок палитры в шапке): «Светлая»,
  «Тёмная», «Океан», «Графит», «Сакура», «Матрица», «Лес», «OLED»; у каждой
  есть светлый и тёмный вариант, кружок «луна» рядом с палитрой их меняет;
- такой же выбор есть и для самой панели:
  «ЧЁРНАЯ» не отдельная тема, а вариант рисунка с инвертированной тушью;
- «Минимал» — не отдельная плитка, а вид темы «Монитор»: переключатель
  «ОБЫЧНЫЙ / МИНИМАЛ» прямо под выбором панели;
- у тем «Монитор» и «Часы» вместо выбора медиа есть «ФОН»: кнопка
  «ВЫБРАТЬ ФОН…» ставит картинку под содержимое кадра (сверху — полупрозрачная
  бумага, чтобы тушь читалась), «СБРОС» возвращает чистый фон темы;
- выбор темы панели переключается «жидким стеклом»: заливка переезжает к
  выбранной плитке, по ходу движения вытягивается, а подписи под ней меняют
  цвет ровно по краю стекла — текст читается в любой момент анимации;
- в теме «Медиа» строки «ПАНЕЛЬ» и «ВИД» неактивны: файл показывается как есть,
  и эти настройки на него не влияют;
- язык интерфейса RU/EN переключается на лету, выбор запоминается;
- кнопка «три полоски» в шапке сворачивает подписи левой панели: остаются
  только контролы, а колонка сужается — превью становится больше. Ширина
  колонки уезжает плавно, подписи растворяются;
- переключатели (темы, окно, панель, вид, вкладки) переезжают жидким стеклом:
  заливка тянется за курсором и садится на выбранный вариант;
- фоном окна служит картинка `assets/backdrop.jpg`: из неё делается маска
  по яркости, поэтому на белой теме рисунок чёрный, на чёрной — белоснежный;
- пресет темы хранит тип, файл медиа, яркость, частоту, цвет акцента
  и вариант панели (`%APPDATA%\TrccSharp\themes.json`).

## Медиа: форматы и поведение

| Формат | Как проигрывается |
|---|---|
| `.png` `.jpg` `.jpeg` `.bmp` `.tif` | статичный кадр, без перерисовки |
| `.gif` | по времени: частота = средняя по задержкам кадров, лишние кадры пропускаются |
| `.mp4` `.m4v` `.wmv` `.avi` `.mov` `.mkv` `.webm` | через `MediaPlayer` в реальном времени, зацикливание по `MediaEnded` |

Строка «частота: N из M кадр/с» показывает, сколько кадров реально ушло по USB.
Практический потолок этой панели — около 10 кадр/с, поэтому видео на 30 кадр/с
играет в правильной скорости, но с прореживанием кадров.

Видео декодируется системными кодеками (H.264 есть в Windows 10/11 из коробки);
если кодек не установлен, в логе появится сообщение от `MediaPlayer`.

## Чего пока нет

- RGB-подсветки помпы: команды `BKL_SET`/`SCR_SET` есть в декомпиляции,
  но их payload для Type 2 не восстановлен.
- Температуры CPU: на AMD нужен доступ к SMN/MSR, без драйвера не читается.

## Производительность

Кадр 240×320 — это ~300 HID-отчётов по 512 байт, поэтому по пути к панели
ничего не выделяется заново:

| Что | Было | Стало |
|---|---|---|
| HID-канал | событие, буфер и `GCHandle` на каждый отчёт (~300 на кадр) | событие, буферы и указатели создаются один раз на канал |
| Поворот растра | `Buffer.BlockCopy` по 4 байта на пиксель | копирование `uint` через `Span` |
| RGB565 | новый массив на кадр | пишется в переиспользуемый буфер, яркость — таблицей подстановки |
| Пакет кадра | новый 512-выровненный массив (150 КБ) на кадр | один буфер на соединение |
| Отрисовка темы | новый `RenderTargetBitmap` + массив пикселей на кадр | один холст и два буфера (пинг-понг) |
| Датчики | `GetSystemTimes` + ADL на каждый кадр | не чаще 2 раз в секунду, в теме «Медиа» — не читаются |
| Фото | рендер 320×240 на каждый кадр | собирается один раз при открытии файла |

Замер: `trcc-probe bench --seconds 5` → ~10,7 кадр/с (1601 КБ/с) — это потолок
самого HID-интерфейса, а не приложения.

## Структура

```
src/TrccSharp.Core
  Hid/            HID-канал (513-байтные отчёты, overlapped I/O)
  Protocol/       профили панелей, handshake, сборка кадра, PanelDevice
  Imaging/        Surface (BGRA), повороты, RGB565, тестовые картинки
src/TrccSharp.App
  Rendering/      отрисовка тем через WPF
  Sensors/        CPU/RAM/GPU без внешних зависимостей
src/TrccSharp.Probe
  диагностика: list / probe / pattern / sweep / bench / gpu
```
